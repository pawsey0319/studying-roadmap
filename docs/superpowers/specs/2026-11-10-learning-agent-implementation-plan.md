# 学习 Agent 分阶段实施计划（语音优先）

日期：2026-11-10。状态：供审阅的可执行计划；本轮不实现产品代码、不安装依赖、不部署、不提交混合工作树。

依据：[统一设计](2026-11-10-learning-agent-design.md)、[模型研究](2026-11-10-audio-vision-model-research.md)。用户已确认：双路径语音先于 Android 跨 App 阅读，其后筛选最小合格模型，最后完善学习会话与双反馈。PC 既定理解/指导/授权执行方案不变，不在手机阶段偷偷移除或重写。

## 1. 范围与工程决策

- 手机包括普通 Android 手机上的微信、外部浏览器等 App。机型不是用户需补交的前置条件；兼容矩阵由开发负责。iPhone不列首轮验收。
- 开启语音按钮：按住说话、松开发音频给真实音频理解模型；未开启：松开转为可编辑文字，由用户发送。默认文字回答，可选朗读；失败不静默转换模式。
- 手机授权持续维护来源上下文，等待用户消息，不主动解说、不默认连续上传视频。阅读权限不等于操作权限。
- 工程建议：复用原生 ESM 前端与 Capacitor 8 壳；语音先独立于读屏打通。手机先采集/交互，推理可用明确授权的电脑/开发者服务，不要求所有模型在手机运行。
- 不改公共内容 ID，不自动 pull/rebase/commit，不借机提交此前路线/UI改动。执行前先记录工作树基线，分阶段审阅差异。

## 2. 每阶段共同完成标准

先写纯逻辑测试与请求契约，再接 UI/原生适配；每阶段独立功能开关、错误码和回退入口。新增模块按项目现有要求检查 preload 清单，不破坏原生 ESM 无构建网页。

验证分层：`node --test tests/*.test.js` 与 `node --check`；请求契约/mock；真实模型；Android原生构建；真实手机生命周期测试。mock通过不算真模型通过，桌面浏览器录音通过不算Android通过。发布需同一签名升级、数据不丢；构建和发布是另行授权操作。

所有限制需服务端验证，不只前端检查；脱敏诊断不存原音频、图片、Key或完整文章。纯本地选择不得静默转云。鉴权、来源CORS和额度保留，不为解决本地预览错误放开所有来源。

## 3. 阶段一：双路径语音（首个实际交付）

### 1A 能力契约与录音状态机

建议新增 `src/core/voice.js`（纯状态机）与 `src/ai/capabilities.js`（能力声明与探测）；改 `src/ui/agentui.js`、`src/ai/providers.js`、`src/ui/settings.js`。文件名为实施建议，非已存在。

状态：idle→requestingPermission→recording→processing→draft或sending→done/error；cancelling可从处理中终止。开始时锁定本次 `mode=direct_audio|dictation`、会话ID、请求ID与来源引用；异步返回不得写入已切换的会话，不覆盖用户录音期间新打的文字。

实现 pointerdown/up/cancel、失焦、移出取消区、双击/多指防重入与可访问等效操作；录音时持续显示“松开发音频/松开转文字”。权限拒绝、设备占用、不支持录音、空录音、超长、取消均有独立反馈。麦克风 tracks 在完成/取消/退出后停止；请求用 AbortController，晚返回结果丢弃。仅点击输入按钮不能误发录音。

参数由配置定义，首轮建议最大录音60秒、单次上传10MiB；这是工程初值，依据选定模型/解码性能下调或调整，前后端保持一致。长音频分段必须验证尾部和口头更正未丢失；不支持则明确拒绝，不截断后装作完整回答。

测试：固定本次模式、取消不发、松开仅发一次、转文字不调用聊天、权限异步期间松手、切会话、组件销毁、超时与迟到结果。

### 1B 两条真实服务链路

ASR保持独立 `transcribe`；新增直接音频适配器接口（建议 `understandAudio`），不能把 `/audio/transcriptions` 响应再发纯文本模型当作direct_audio。能力分别声明 `dictation`、`audioUnderstanding`、`imageUnderstanding`、`tts`、工具能力；“OpenAI兼容”不等于全部支持。

候选验证：ASR先接一个许可复核通过的可用模型；直接音频商业路径优先Omni7B或MiniCPM-o4.5，研究3B仅非商用。先验证完整链路，不等待全部候选评测；具体endpoint与凭据由部署配置提供，不能编造可用平台模型。无真实服务时只可交付mock结果并标明缺失，不宣称阶段通过。

服务适配保留MIME，校验实际容器/时长并解码重采样；模型收到波形/音频特征才算音频理解。可由音频子模型输出答案或结构化观察供主Agent调用工具，记录真实音频模型ID，不把观察冒充用户原话。模型输出同样不可绕过工具授权。

平台代理改动涉及 `cloudbase/functions/ai/lib.mjs` 和入口：受限类型的多模态schema、字节/时长上限、可用模型白名单、鉴权、额度、超时与取消；不能继续过滤数组/音频附件再按纯文本回答。若函数网关不适合上传，使用独立临时媒体入口+短期对象引用：每次访问校验所属用户、TTL、大小，禁止任意远程URL抓取以防SSRF；取消/超时/过期清理。具体是否独立服务在1B技术验证中决定，不默认现有云函数能托管权重或大文件。

历史会话保存音频事件与可选辅助转写，不默认重发所有历史录音；临时录音按设计清理。直接音频可仅文字输出，朗读是独立可停TTS，不能挡住主链路。

测试：ASR留草稿可编辑再发；direct_audio确有音频输入证据；同录音两路互不串；不支持能力明确失败；401/403/429/超时/坏格式/超限/取消；媒体隔离与过期删除。真链路至少覆盖中文、夹英文、数字/否定、自我纠正、静音与噪声。保存模型revision和请求模式，不保存原音频进普通日志。

### 1C Web与Android验证及门槛

检查 `src/native.js` 与 `app/native/MainActivity.java` 的WebView麦克风行为；只有浏览器录音路径不足时才加原生录音适配，不先重复造两套。所需Manifest权限与注册改 `app/patch-android.py`、`app/native/`，不手改被忽略的生成工程作为唯一实现。

门槛：两路真实服务均通；默认文字答复；所有取消/拒绝/切会话用例通过，无意外发送；真机录音时麦克风状态与资源释放正确。未配模型时清晰禁用相关模式；不能把仅mock演示标记为语音功能完成。

## 4. 阶段二：Android跨App阅读

依赖阶段一可用输入链路；不等待最小模型最终定型。先做采集与来源连续性的技术验证，再做完整界面。

### 2A 来源与原生采集

建议新增 `app/native/ScreenContextPlugin.java`、`ScreenCaptureService.java`，经现有patch复制并注册；JS桥在 `src/native.js`，上下文状态机建议放 `src/core/screencontext.js`。具体类名由开发确定。原生只接受窄参数，不能让网页传任意系统Intent或文件路径。

MediaProjection必须系统授权，前台服务/持续通知，onStop清理、锁屏/退出释放、进程重建不得复用token。首轮不做无障碍点击或任意远控；悬浮入口权限独立且可拒绝，不能要求无障碍权限仅为了OCR。

先实测两种入口：A单App共享+咨询切换；B回到来源App使用可选悬浮咨询入口。Android共享能力、厂商后台限制会影响A；只有证据支持才能选。悬浮可能进入整屏采集画面，需要测试排除自家窗口、裁剪来源或采集时隐藏浮窗，不能将咨询UI当源内容；不在浮窗录音阶段随意隐藏导致丢pointer事件。悬浮不可用时提供明确暂停/返回来源/截图分享，不将静态分享冒充持续读屏。

App内能取正文先用正文；外部App默认仅获准可见画面，不假定读DOM、后台全文或聊天记录。新页面许可：咨询页先显示来源预览、允许确认；页面/域变化按设计重新确认。不依赖视觉猜测来源包名/URL，无法可靠判断变化时将其标记不确定并要求用户确认当前来源，不可默默继承。

### 2B 上下文刷新与推理

source记录来源类型、已知标题/包、授权session ID、frame ID、获取时间、版本/hash与有效状态。按页面变化/用户返回/提问更新并限频，空闲不持续推理。提问时核验来源新鲜度；过期、受保护、共享终止或只看到咨询页就暂停并说明。

采用画面差分/去重减少重复发送；模型调用仍按需，不将变化检测变成全天外传。只保留必要内存帧，默认不持久化；截图上传去向显式告知。应用内许可与OS许可缺一不可。

### 2C 阶段验收

微信文章和外部浏览器各完成：来源→咨询授权→问当前段落→回源滚动→第二问引用新内容→撤权立即停；拒绝不采集。记录帧ID/时间证明不是旧图。覆盖旋转、锁屏、前后台、系统杀进程、系统结束共享、受保护/黑屏、网络失败、自家浮窗遮挡及内容注入。

兼容矩阵由开发建立：先声明受支持的API范围，对Android14前后授权与单App共享差异分组，覆盖较新版本停止行为及至少两类厂商后台限制；模拟器测协议不能替代真实设备采集。当前无需用户提供机型。不可满足时报告具体链路限制并调整入口，不以“普通安卓均支持”掩盖失败。

阶段门槛：两类来源真实更新可验证，撤权停止通过，旧帧不冒充实时，无越权采集/外发。界面漂亮、能读单张截图不算达标。

## 5. 阶段三：选最小合格模型

依赖前两阶段已提供真实输入链路与失败样本；不逆转为先跑所有榜单才做功能。

采用研究报告的240例初始固定集与分层指标，分ASR/直接音频/阅读视觉/PC界面。保留开发集、冻结验收集；所有revision、框架、量化、输入预算、设备/服务器条件固定可复现。

- ASR：Paraformer220M、SenseVoice234M（许可通过后）、Whisper-small，对照Qwen3-ASR约0.9B；tiny/base只作下界。
- 直接音频：研究Omni3B；商业Omni7B与MiniCPM-o4.5，评测仅音频/仅文字输出配置，实测模块是否卸载。
- 视觉：正文无模型提取；Qwen3.5-0.8B/2B、InternVL小型对照，PC用Qwen3-VL4B基线，扫描表格按需PaddleOCR-VL1.6。

产出评测manifest、逐例结果、质量/延迟p50/p95/峰值内存/成本/许可表、错误分桶与最终推荐。研究报告的准确性门槛是初值非实测事实；若预算内无人通过就升级模型/请求澄清/明确不支持，不下调高风险信息正确性只求小。量化后全量复测关键数字/否定/小字。

选定配置按版本发布，可回退前一验证配置；不因模型更换新增未授权的数据外发。PC执行授权仍由Harness控制，不交给VLM坐标输出。

## 6. 阶段四：学习会话与双反馈

前三阶段从一开始就保留必要session/request/source ID与停止事件；此阶段完善产品化存储，不是此前允许丢记录或无限留媒体。

建议新增会话/事件/证据/检查点存储与UI，复用 `src/store/`；先确定schema、迁移、附件TTL与删除索引，避免大媒体挤入feedback小文档。续接校验来源版本和设备映射，重新授权，不重放旧执行。任务完成不自动改掌握度。

修 `src/ai/harness.js` 导出覆盖历史spec的问题；unknown版本不补当前值。个人学习反馈保持私有；质量反馈新增明确预览/逐项附件授权、管理者入口与权限，不把已有私有feedback静默搬到后台。管理员不可获得终端执行权限。

先落地人工评测与审核发布，再接定时候选分析、隔离测试、签名/灰度/回滚；候选模型无生产发布密钥。本计划不创建机器定时任务。云同步与质量提交分离；删除会话/反馈处理关联附件和评测样本。

验收：关闭重开可回看并续接、来源变化可察觉；拒绝上报不影响使用；用户不能枚举他人反馈；管理员看到的只有同意材料；旧版本导出准确；回滚不冒充撤销已执行的数据变更。

## 8. PC并行边界与后续决策

PC总体设计保持：Mac先贯通理解/指导/授权执行，目录/编辑器/受控工具与屏幕互补，Windows随后。共享阶段一语音和阶段三模型适配，但不把Android完成等同Mac伴侣完成；桌面伴侣实现另列工作包，在用户批准对应计划后推进。

无需再向用户索要安卓机型。实施中由开发作出并记录的决策：支持的Android API范围、具体模型服务与凭据配置、录音限制、媒体存储/解码方案、浮窗是否可行、性能预算与发布渠道。若会改变已确认的双语音语义、外部App正式范围、授权边界或数据去向，则必须先说明并征得用户同意，不静默降级。
