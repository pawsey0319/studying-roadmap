# 第一阶段双路径语音：实现与验收状态

日期：2026-11-10。状态：代码与模拟链路已实现，**真实模型、Android 真机验收未完成，不是发布通过**。

## 已实现

- 默认语音模式关：按住说话，松开只调用转写接口，追加到已有输入草稿，不自动发给聊天模型。
- 点击语音模式开关后：按住说话，松开将录音实际解码为单声道 PCM16 WAV，通过独立音频理解服务的 `input_audio` 发送，默认文字回答。不是把转写交给文本模型。处理失败不会静默切到转写。
- 两路都支持取消，按下锁定模式/会话，移出松手取消，关闭/切会话/失焦/隐藏取消；权限等待期间松手不录音，迟到 stream 停止，迟到响应不写当前会话。
- 可访问等效入口“点击开始／结束”；配置等待期间第二次点击取消。短于300毫秒的录音不发送，避免普通短点击误发。
- 单次录音最长60秒、录音容器10MiB上限；服务适配器25MiB上限作为第二道保护，转换后同样受限。处理阶段120秒 deadline，超时终止，不自动重试；重试需用户重新录音。
- 直接音频成功后只保存事件占位、回答与模型名称；原声不存入聊天记录，不写普通日志。原声释放是停止引用，非保证 JavaScript 堆即时物理清零。未实现原声回放/恢复/上传对象存储。
- 平台代理当前仅文本，遇到多模态内容明确400，不能悄悄过滤附件后按文本回答。此改动仅在仓库，未部署。
- Android 生成工程补丁加入 RECORD_AUDIO 声明，不自动授权；运行时 WebView/系统权限仍须真机验证。

## 配置与兼容范围

在设置→AI 服务→语音设置分别配置：

1. 转写 `sttBase/sttModel/sttKey`：OpenAI兼容 `/audio/transcriptions`；非平台的聊天配置可作为转写默认值，但不表示服务支持该端点。
2. 直接音频 `audioBase/audioModel/audioKey`：支持真实 `input_audio` 的 `/chat/completions`，音频模型需要文字输出及兼容流式或JSON响应。不继承平台模型地址、文本服务密钥。无鉴权本地接口允许独立 Key 留空。

配置就绪不等于远端能力已验证。直接适配器仅接受 WAV/MP3，录音由浏览器 AudioContext 解码后编码为 WAV；浏览器不支持解码则明确失败，不改后缀冒充转换。请求16000Hz，但使用实际解码采样率写头，服务必须验证兼容；尚无强制重采样回退。直听本轮只回答，不执行工具；不使用未验证的音频token估算展示真实音频账单。默认文字与可选朗读属于独立链路，本轮没有新增TTS实现。
