# 现场学习 Agent：理解、指导与授权执行统一设计

日期：2026-11-10
状态：设计草案，待用户审阅；不代表已实现或已同意全部技术选择。

## 1. 产品定位与已确认原则

这是跨领域的现场助手，不是只面向程序员的代码阅读器，也不是强制授课系统。它结合用户正在看的材料、当前界面与已授权的项目，既可以解释，也可以逐步指导，还可以在授权范围内直接完成任务。

用户已确认：
- 理解知识与完成操作必须同时支持；计算机场景先验证，但不能把产品收缩为安装向导。金融、法律、艺术等领域也有理解和实践两面。
- 讲不讲、讲多深、用户操作还是 Agent 执行，由用户决定；赶任务时直接完成，不插入强制测验或教学。
- 三种意图可在同一会话随时切换，不必换窗口、复制材料、重讲背景。
- 音频入口是按住说话，不是上传音频文件；默认文字回答，可选择语音。
- 保存每次任务，方便回看、复做、继续。任务完成不能自动标记为已经掌握。
- 分开个人学习改善与管理者 Agent 改善；希望定时由模型提出改进，经开发者审查后发布。

本设计的技术选择均为建议，不冒充用户已确认：Mac 先行、轻量桌面伴侣、结构化工具优先、下述保留期限与试运行门槛。选择 Mac 是因为当前有测试机，不是断言它比 Windows 普遍简单。

## 2. 范围、非目标与失败形态

目标：让不会代码的大一新生打开项目后，直接问“这段在干什么”“带我跑起来”“直接帮我修好”，得到基于实际材料的回答和可验证结果；同一机制也能用于读报告、合同学习、创作工具操作等。

不做：用户自建 Agent/编辑系统提示词/安装任意执行插件；默认全天录像监听；把所有历史不断塞进模型；未经审查自动升级线上 Agent；首版任意应用无人值守控制；代替法律、投资、医疗专业判断。

失败形态：只能读截图却宣称读懂项目；屏幕共享等于操作授权；把执行成功算学习掌握；模型回复“做完了”却没有结果证据；原始材料默认进管理者收件箱；让不同领域变成互不相通的多个机器人。

## 3. 用户体验契约（非最终界面稿）

### 3.1 同一会话的三种意图

| 用户说法 | 行为 | 完成依据 |
|---|---|---|
| 帮我理解 | 引用材料定位，解释并允许追问 | 用户问题得到有依据的回答，不强制考试 |
| 带我操作 | 给当前一步，观察用户操作结果后再继续 | 状态或用户确认与目标一致 |
| 直接完成 | 先说明执行范围，授权后调用工具，简短汇报 | 实际产物、测试、界面或工具结果 |

不要求用户每次选模式；自然语言可覆盖默认意图。用户说“先别动”立即转为只读；说“刚才为什么这样改”在原会话解释真实变更。意图不清且会造成写入时，先澄清，不能默认执行。

### 3.2 双路径按住说话与语音回答（2026-11-10 用户修订）

语音按钮控制输入模式，与是否朗读回复分开：
- 开启语音模式：按下录音，松开即将音频消息直接发送给 Agent，走能真实接收音频的模型/适配器；不能静默变为只发 ASR 文字。可附辅助转写，但转写不替代模型接收音频。
- 未开启语音模式：按下录音，松开转为文字放入输入框，用户编辑并主动发送，不自动发送。

取消手势/失焦/pointercancel 不发送；按下时固定此次录音模式，中途切换不改变此次发送语义。提供键盘或点击开始/停止的等效入口。空录音不发，识别失败/断网保留本次重试机会；直接音频模型不可用时明确报错，用户明确选择后才可改为转文字，不能偷偷降级。录音时清晰标示“松开发音频”或“松开转文字”。

用户输入音频不等于 Agent 必须输出音频；默认仍文字答复，可独立开启朗读。只朗读给用户的答复，可随时停止，不读工具日志或密钥。TTS 不可用时文字仍完整；首版不承诺实时全双工语音。

录音、看屏幕、读项目、写文件、运行命令分别授权。录音不会自动打开屏幕共享。语音口头同意不能替代高风险动作的可审计确认。

### 3.3 现场上下文

悬浮入口只显示当前任务、当前共享对象、暂停/停止与输入；详细记录仍在工作台，不重新增加与“我的/搜索/公共区域”并行的复杂主导航。此处只定义交互契约，像素布局留给后续界面稿。

屏幕不是默认持续推流：用户选择窗口/屏幕，开始后显示明确状态；按提问、操作后、页面显著变化获取必要帧并限频。暂停立即停止新采集；撤销授权中止待执行动作。缩小到单窗口、局部区域优先于全屏。

Agent 应能说明本轮用了什么：例如“当前编辑文件第 20–45 行 + 项目配置 + 刚才终端报错”，而不是“我看过整个项目”。窗口切换、权限失效、屏幕过期时重新观察，不能沿用旧坐标操作。

手机阅读咨询（用户新增要求）：点击“咨询”跳转进入会话后，询问是否授权读取来源页面；授权后在本次页面会话持续更新阅读上下文并等待用户消息，不主动讲解/插话。拒绝时仍可普通对话，不能默认读屏。“持续”表示授权期间保持来源监听与最新上下文，不意味着每帧发送给云模型或后台全天采集。暂停、关闭咨询、撤权或系统结束共享后立即停采；新页面/新域名不继承原页面许可。提问时校验来源版本与可见范围，不能拿 Agent 自己的聊天界面当文章。

用户已确认：手机以普通 Android 手机为首个验证平台，来源包括微信、外部浏览器等其他 App，不以具体机型作为需求前置；iPhone 不列入首轮验收。两类来源均属需求，跨应用不是可选扩展，但不默认技术已实现：App 内页面优先从应用阅读层取正文/选区/滚动位置与变更事件，图片图表按需视觉解析；跨域 WebView、系统浏览器及外部 App 不假设可直接读 DOM。外部 App 只能走系统允许的屏幕共享/分享入口，App 内授权对话不能替代 OS 许可，也不能保证跳转到咨询后仍能读取未展示的外部页面。具体系统版本兼容矩阵由开发验证，不再要求用户先提供机型；受保护页面无法读取时必须明示。PC 方案不变。

## 4. 技术方案取舍

| 方案 | 优点 | 根本限制 | 决策建议 |
|---|---|---|---|
| 仅网页 | 复用现有站点；材料导入和手动屏幕共享较快 | 不能成为可靠的跨应用悬浮控制器，目录/系统能力受限 | 保留为记录与轻量入口 |
| 桌面伴侣 + 共用 Harness | 本地文件、悬浮窗、系统授权与执行可统一管理 | 新增打包、签名、升级、安全桥维护 | Mac 首个现场闭环采用 |
| 全部依赖截图坐标点击 | 通用表面覆盖较广 | 慢、易误点、不能理解完整项目 | 只作为后续明确授权的兜底，不作首版主路径 |

桌面建议 Electron 承载现有原生 ESM UI，加最小原生权限桥；是实施建议，不在本轮安装或脚手架。渲染层不开放 Node.js，使用 context isolation 与窄 IPC；工具在受控本地执行端运行。打包前验证 Mac 签名/屏幕授权/Accessibility 与升级策略；如果 spike 证明现有技术栈不适配，再比较 Tauri/Swift，不先全面重写。

部署结构：现有 Web/安卓记录入口 ↔ 用户会话存储；Mac 伴侣 ↔ 本机工具执行端 ↔ 模型适配器。云端承载账号、可选同步、质量反馈、评测和版本发布，不把桌面权限搬到云端。

本地模型是独立推理路径而非产品边界：能力探测区分文本、视觉、工具、ASR/STT、直接音频理解、TTS，不能用一个音频开关混淆转写与真实音频输入。文本模型不能直接看图，需显式 OCR/视觉适配或提示无法理解图像；工具调用能力不足时降级为理解/指导，不伪装执行。纯本地模式禁止静默转云，STT/TTS 也须本地或关闭。云模式在发送前显示数据去向；API Key 存系统凭据库，不进会话同步。

## 5. 上下文与工具体系

### 5.1 证据来源与选择顺序

优先使用可靠结构化来源：编辑器当前文件/选区/未保存缓冲区、已授权目录文件、文档页码与段落、终端输出、浏览器 DOM/可访问树；截图补充空间与视觉信息。没有相应集成时明确降级，不把“当前可见”当“全部内容”。

首个 Mac 闭环覆盖：选定项目目录、VS Code 当前文件/选区（适配器）、受控终端命令、伴侣内受控浏览器与已授权窗口观察。其他编辑器只读文件兜底，未保存内容不可见时提示保存或另行授权。外部网页没有扩展/DOM 集成时只承诺观察与指导。

目录授权默认为只读，按需检索相关文件；排除凭据、.env、私钥、依赖/构建大目录，遵循忽略配置；符号链接逃出根目录须拒绝或重新授权。项目内 README/注释/网页内容均是不可信材料，不具有修改权限策略的资格。

每条上下文带 sourceId、来源类型、位置、采集时间、版本/hash、可用范围。压缩保留出处和不确定性；工具结果先提炼再进入下一轮。重要结论可追到具体材料版本，而非只有模型自述。

### 5.2 Harness 分层

借鉴 DeepSeek Harness 的“模型外执行框架”思想，不声称复制其全部实现或已经兼容插件协议。

1. Spec/Release：开发者维护提示词模板、工具 schema、策略、评测及版本。
2. Context：按任务检索并组合档案、会话摘要、材料证据与当前观察。
3. Model adapters：统一文本/视觉/工具调用、STT/TTS 能力与错误语义。
4. Loop：理解目标→取证→提出下一步/请求授权→执行或指导→验证→记录。
5. Policy：由执行端强制校验，不能仅靠模型“遵守提示词”。
6. Session/Event log：意图切换、材料引用、工具结果、授权与检查点可追溯。
7. Feedback/Eval：个人反馈与质量反馈隔离；离线回放不执行真实副作用。

工具接口分读写：observe_window、read_file、search_project、read_document、get_editor_context；patch_file、run_command、browser_action。工具名仅为设计示意，schema 留给实现计划。每次调用携带 taskId、授权范围、目标版本与超时；写入前检查前置状态，写后重新读/测试。工具自身返回真实成功/失败，不依据模型解释生成成功状态。

## 6. 权限、风险与失控防护

| 类别 | 例子 | 策略建议 |
|---|---|---|
| 观察 | 当前窗口、指定项目只读 | 按对象和会话授权，可随时撤销 |
| 有限可恢复写入 | 指定目录 patch、已许可的本地测试 | 展示计划/差异，允许用户授予本任务批量范围；仍做版本检查、备份与日志 |
| 高影响动作 | 删除、安装软件、联网下载、对外提交/上传、发消息 | 展示确切对象/目的地/影响，单次显式确认；不能用“直接完成”概括授权 |
| 敏感或不可安全控制 | 转账交易、密码/验证码输入、真实法律提交、医疗账户操作、提权 | 首版不执行，用户亲自处理；可提供非专业替代判断的说明 |

不能靠命令名白名单就安全运行 shell：脚本、依赖安装和测试也可能联网/改文件。执行端默认隔离指定工作区并限制网络；无法有效隔离的命令降为逐次确认且明确说明，不自动运行。首版禁止提权、破坏性全盘命令和无边界后台进程。

授权绑定具体工具、路径/域名/应用、动作类别与任务有效期；撤销/到期即拒绝。防止路径穿越、symlink 绕过、脚本子进程扩权；目标内容变更时重新验证授权对象。DOM/文件结构工具优先于坐标；坐标动作前验证窗口身份、屏幕尺寸与最新帧，用户接管后暂停自动操作。

“立即停止”中止后续调用、终止可控子进程并记录部分结果；已发送请求/外部写入不保证撤回。恢复以检查点与文件备份为依据，不承诺撤销任何外部动作。新会话或跨设备继续不继承旧执行授权。

金融/法律材料可用于经授权的阅读理解；不因此开启交易、正式签署、提交等敏感代办。敏感数据云处理另有披露和授权要求。

## 7. 会话保存与回顾

### 7.1 记录什么

Session：任务目标、领域、关联路线、意图变化、状态、设备、版本、摘要、下一步。状态区分进行中/等待用户/暂停/完成/失败，不另造“任务完成=掌握”。

Evidence：材料 locator（项目别名+相对路径/符号/行区间、文档页段、URL）、当时版本/hash、可选最小摘录或必要快照。行号仅为提示，复开时以版本/符号校验，文件已变更则标“来源已变化”，不假定位成功。

Events：解释、提问、卡点、步骤、用户/Agent 操作主体、工具结果、确认、错误、验证与恢复信息。保存可审计的动作摘要和证据，不保存模型隐藏思维链。

Checkpoint：当前步骤、已完成产物、尚缺条件、环境摘要、材料引用。个人学习条目仅在用户反馈/明确证据时提出，路线/掌握度变更由用户确认；不要求为完成任务强行做测验。

### 7.2 如何回看与继续

主视图是任务卡：做了什么/结果、遇到的问题、讲过什么、下一步；可展开时间线和材料定位。支持搜索、收藏、导出、删除、关联笔记/路线；“继续”重新检查材料与环境并请求必要权限，不直接重放旧命令。“复做”创建新尝试保留原记录。

建议默认本地保存文本摘要与事件；原始音频不长期保留：转文字路径在识别成功并保留文字后释放，直接音频路径在模型处理完成且不再需要本次重试后释放临时录音；屏幕帧默认仅内存短期使用，不做全天录屏。用户选择保留的截图/摘录单独标记，删除会话同时删除其附件与索引。云同步为显式可选，首版只同步摘要/文本事件，原始项目与屏幕媒体不自动上传。

未发送录音取消即丢弃；处理中断最多保留至本次重试/退出，用户可立即删除。云端使用模型的实际保留政策需在选用供应商后核实披露，不能因客户端删除就宣称供应商已立即删除。

跨设备显示可同步记录，但项目路径用设备本地映射、不得同步绝对路径/密钥。重新关联项目与校验版本后才能继续本地操作；找不到材料仍可看记录，不伪造现场状态。离线可回看，本地模型可继续其具备的能力；云请求失败不丢任务草稿。

## 8. 双反馈严格分流

| | 个人学习反馈 | Agent 质量反馈 |
|---|---|---|
| 目的 | 调整本人的解释深度、节奏、薄弱点与续学 | 改善所有用户的 Agent |
| 例子 | 还是没懂、讲短点、我已会、下次继续这里 | 事实错、忽略材料、误操作、引用错、太慢 |
| 默认去向 | 本人私有会话/档案，可选私有同步 | 未提交前也只本地；用户预览并授权提交后进入管理者服务 |
| 生效 | 当前会话可立即调整，持久档案可查看/纠正/撤销 | 不直接改当前线上 Spec，只进入候选迭代 |

不能把“已登录同步”当成“同意开发者读我的材料”。质量反馈默认只含原因、可编辑描述、任务类型、Spec/工具/模型版本、脱敏错误码与随机反馈 ID；引用回答、材料摘录、截图/音频必须逐项选择。提交前预览；自动脱敏是辅助，不是隐私保证。

新增服务端质量反馈入口与管理员收件箱，普通用户不能枚举他人反馈；管理员最小权限并留审计。建议反馈明细保留 90 天后清理，聚合统计去标识；用户凭反馈 ID 可申请删除，删除关联评测样本。已发布版本无法抹除的泛化知识变化需在政策说明，不能承诺“撤回反馈会回滚模型”。期限和法律文本上线前复核。

现有 feedback 私有文档继续作为历史记录，不能静默搬到管理员收件箱。迁移旧版本保留原始来源与版本；未知版本标 unknown，不拿当前版本补写成历史事实。

## 9. 模型辅助的开发者迭代闭环

这是待实现的产品后台能力，不是在本次助手会话创建定时任务。

建议每日聚合质量/失败率，新增有效反馈达到 20 条或每周触发一次候选分析；样本不足时输出“证据不足”，不硬改。严重权限/隐私事件直接告警、暂停相关能力，不等周报。

流程：接收同意提交的反馈→去重脱敏/归类→提炼可复现问题→在隔离分支生成提示词/工具/策略候选与新增测试→离线回放→出具差异、覆盖、风险和成本报告→开发者审查→签名版本发布→小范围灰度→监控与回滚。

候选模型没有生产发布密钥、用户机器执行权限或主分支写权限。反馈文本按不可信输入处理，不能把用户要求“关闭确认”转为策略。安全策略削弱、隐私条款变化、依赖/工具权限扩大必须显著标注并人工专项审查。离线回放使用模拟工具和脱敏夹具，禁止重放真实付款/删除/外发。

版本清单固定 Spec、模板 hash、工具 schema、策略、模型配置与应用最低版本。会话开始固定兼容版本；普通更新不在执行中热换，安全禁用可立即阻断并告知用户。灰度建议 5%→25%→100%，每步至少一个完整观察周期，样本不足延长而非自动放行。旧客户端不支持新权限协议时拒绝执行并提示升级。

保留上一稳定版本与数据库兼容方案；回滚应用/Spec 不等于撤销已发生的用户数据变更。当前 FNV 指纹只能定位，不是安全签名，正式发布需可信签名/校验。

## 10. 分期与验收

### 阶段 0：修清现状与能力基线

不新增现场控制，先明确平台支持：平台代理 cleanBody 当前只收 string content，不能宣称平台图片已经可用；历史反馈导出版本覆盖问题需修；长按说话需替换当前点击开始/结束；管理者收件箱、TTS、桌面执行尚不存在。本轮仅记录，不改代码。

验收：模型能力探测真实可用；文本/图片/直接音频/STT 请求成功与失败路径、大小限制、鉴权、CORS、额度都测试；不支持能力显式禁用而非丢掉图片继续答。保留现有路线/导航改动与公共 ID，不把升级变成全站重写。

### 阶段 1：Mac 有边界的完整闭环

必须贯通理解、用户操作指导与至少一种授权直接执行，不能以只读原型冒充完整首版。覆盖双路径按住说话（直接音频发送/转文字后用户发送）与文字、可选 TTS、窗口观察、指定目录读取、VS Code 上下文、受控 patch/命令/内置浏览器、停止、事件记录与继续；默认不做任意外部应用坐标操作。质量反馈提交及开发者手动评测/审核发布闭环同期建立，先不自动定时改代码。

验收场景：
1. 新生打开示例项目，无需复制代码，解释入口函数并定位具体文件；切到“带我运行”，用户执行后识别实际报错；再说“直接修好”，授权 patch 后测试结果可查。
2. 打开一份报告或合同学习样例，解释一段、引用页段，再协助完成一个有边界的本地整理任务；不代作投资/法律承诺，验证不是计算机专用产品。
3. 完成任务后关闭重开，看到产物、卡点、解释和下一步；项目改变能识别，继续时重新授权；掌握度没有被自动加满。
4. 取消录音、拒绝共享、撤销写权限、模型超时、停止执行均不丢记录，不越权重试。

### 阶段 2：自动候选迭代、Windows 与更广集成

在人工链路和评测稳定后启用定时候选分析/隔离 PR，不自动批准发布；Windows 复用共用协议，重新验证屏幕采集、UI Automation、路径与命令隔离、签名升级；扩展浏览器/文档/创作工具连接器。通用坐标执行需单独安全验收，不因已支持 Mac 就默认可用。

### 手机边界

现有安卓 Capacitor 外壳优先提供双路径按住说话、图片、阅读咨询授权与会话回顾；App 内阅读页授权后持续维护来源上下文并等待用户提问，微信、外部浏览器等跨 App 阅读已纳入正式范围，普通 Android 手机优先，不承诺所有 App 的所有页面均可读取。跨应用观察需要原生 MediaProjection，每次会话授权与前台提示，切换到咨询不保证原页面仍可采集，浮窗/无障碍执行是另一个权限与政策问题。iOS 不承诺第三方任意应用上常驻悬浮与控制；先评估系统录屏/共享入口或单次屏幕材料，执行以应用内/获准连接器为界。远程继续桌面任务属于额外产品能力，不把记录同步等同远控。

### 发布门槛（建议，需实测校准）

建立至少 30 个固定任务：10 理解、10 指导、10 执行，至少 10 个来自非计算机场景；另有独立安全对抗集覆盖注入、撤权、越界路径、敏感外发及陈旧截图。
- 阻断性越权用例全部通过，出现一次未授权外发/写入不得发布。
- 工具执行完成结论必须有证据；引用定位正确率目标 ≥95%；固定任务完成率目标 ≥85%，且相对当前稳定版不退化。
- 分开统计任务完成率、用户可选的理解反馈、7 天内续学成功率，不能合并为“学会率”。
- 分别测量转文字路径松开至可编辑文字、直接音频路径松开至首个有效答复、文本首字与单步执行的 p50/p95，按设备/本地与云模型分组；不在模型和硬件未选定时承诺统一实时延迟。记录图像 token、音频、工具成本及每任务预算，触顶停下询问。
